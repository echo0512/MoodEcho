# 语义搜索维护说明

## 检索流程

查询最多500个UTF-16字符。读取当前用户正式、未删除的日记，合并标题/正文文字包含匹配与分块向量结果，按日记去重。精确标题优先；其他候选融合片段相似度与查询词覆盖率，取Top K。默认返回10篇，最多20篇；前端仍按日期分组。

正文按段落和句子拆分，每片段最多350个UTF-16字符，长段落的相邻块重叠50字符。标题也分块。每篇取满足门槛的最高片段相似度；摘要取正文命中附近或最相关正文片段，不重复标题。

查询词按汉字双字词组、英文/数字词切分，按用户语料逆文档频率加权覆盖率。非精确标题候选排序分为：

```text
semantic + lexicalBoost × (0.75 × coverage + titleContainsBonus)
```

标题包含查询时bonus为0.25，其余为0。纯文字候选的排序基准使用普通语义阈值，返回的score为null；有向量匹配时score是相似度，不是置信概率。

| 环境变量 | 默认值 | 用途 |
|---|---:|---|
| SEMANTIC_MIN_SIMILARITY | 0.45 | 普通片段门槛 |
| SEMANTIC_SHORT_TEXT_MIN_SIMILARITY | 0.65 | 短片段门槛，不低于普通门槛 |
| SEMANTIC_MIN_TEXT_LENGTH | 6 | 普通片段的最少字母/数字数量，汉字计入 |
| SEMANTIC_LEXICAL_BOOST | 0.12 | 文字覆盖率加分权重 |

少于3个字母/数字的片段不独立参与语义召回，但允许文字匹配。上述参数是启发式设置。

相关日记使用整篇表示：标题和正文合计不超过2000个UTF-16字符时直接生成，否则聚合片段单位向量再归一化。2000是输入字符预算，不是模型token上限。

## 后台索引

保存日记和任务入队共用数据库事务。每篇一个持久化任务；再次编辑递增revision。worker通过 `FOR UPDATE SKIP LOCKED` 领取任务，使用claim_token防止旧worker覆盖新回执；外部请求期间不持有任务行锁。发布完整向量快照前锁定日记、核对内容指纹。

失败最多尝试5次，以15、30、60、120秒间隔重试；最终进入failed。处理中任务租约为30分钟，过期可重新领取。删除日记取消任务，物理删除通过外键级联删除任务。

服务未配置或禁用时不领取任务、不消耗重试次数。客户端每批最多10条文本，连接超时3秒，读取超时5秒。

`diary_embedding.embedding` 保存版本、维度、整篇向量及片段文本/向量的JSON快照。旧数组格式或内容指纹不匹配的索引不参与检索。模型名称必须与当前配置一致。

## 接口与恢复

以下接口均要求登录，操作范围限定为当前用户：

- `POST /api/diaries/semantic-search`：请求 `{"query":"想家时的记录","limit":10}`，返回现有 `ApiResponse<List<SemanticDiaryResultVO>>`，data仍是数组。
- `GET /api/diaries/{id}/related`：查询相关日记。
- `POST /api/diaries/semantic-rebuild`：安排当前用户正式日记后台处理，返回安排篇数，不表示处理完成。升级旧索引、换模型或失败重试时可调用。
- `GET /api/diaries/semantic-status`：返回pending、processing、ready、failed计数、最后完成时间及服务配置状态。available只表示配置齐备，不是实时连通性检测；ready不保证纯图片日记拥有向量。

旧数据库先执行README中的任务表迁移，再启动后端并安排重建。新建、编辑和发布会自动安排索引。当前页面没有进度轮询或批量重建按钮。

模型失败时，有文字命中则返回文字结果；没有文字命中则保留服务错误。正常完成且没有匹配时返回空数组。当前接口未增加降级或处理中元数据。

## 测试与限制

运行 `cd backend` 后执行 `./mvnw test`。保留检索、向量客户端和任务单元测试，以及需独立数据库配置的SQL集成测试。测试不调用真实模型。

当前仅使用文字与分块向量融合，没有候选重排、事实核验或向量数据库。主题相似不能保证人物、数值、否定、计划/完成状态符合查询；短片段可能丢失上下文，取最高分可能偏向长日记。阈值不能理解为准确率承诺。

每次查询仍读取当前用户语料并在Java内扫描向量JSON，规模增加会带来解析、内存和延迟开销。编辑会重算片段。真实容量和端到端时延需结合实际部署测量。
